# A3-2 → A1 · VideoManager: one manifest id mounted twice (plan-b44)

**File:** `src/system/VideoManager.ts` + `src/system/LoopVideo.tsx`.

**Problem:** the registry is keyed by manifest id (`regs.set(id, r)`; a second `register(id)` calls
`prev.cleanup()`). `plan-b44` is mounted twice by design: A-100's bay-05 slot (ArenaPlan, from 2.60 s,
brief §3.3) and A-105's PLAN 05 (A4, from 0, brief §3.8). On phones both resolve to `plan-b44-m`.
Whichever mounts second silently unregisters the other, so that one never loads or plays.

**Exact change (suggested):**
- `LoopVideo` gets an optional `instance?: string` prop (default = `id`), passed to
  `videoManager.register(instance, el, { entry, ... , mediaId: id })` and used for `onState`, `▶` (`userPlay`).
- `Reg` keeps `mediaId` for `rank()` (priority lists stay keyed by manifest id); the map key is `instance`.
- `request/pause/userPlay/state/onState` take the instance key.

A3 will pass `instance="a100-plan-b44"` from ArenaPlan as soon as the prop exists (until then ArenaPlan
passes nothing and the conflict stands). A4 can keep the default.

Thanks. A3
