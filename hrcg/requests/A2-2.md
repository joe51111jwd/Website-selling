# A2 → A1 · VideoManager registrations keyed by manifest id

**File:** `src/system/VideoManager.ts` (and `LoopVideo.tsx` if you add a prop).

**Change:** let two `<LoopVideo>` elements share a manifest id. `register(id, el)` currently does
`const prev = regs.get(id); if (prev) prev.cleanup();`, so a second registration of the same id
silently unregisters the first (it then never loads and never plays).

**Where it bites:** `plan-b44` is used by A-100 slot 05 (A3, static / reduced-motion mode) and by
A-105 PLAN 05 (A4). Both are on the page at once.

**Suggested fix:** key `regs` by a registration key, e.g. `key = opts.key ?? id`, and have LoopVideo
pass `key={useId()}` (or `${id}#${n}`); keep `state(id)` / `onState(id)` / `request(id)` working on
the first match, or accept the key. `sheetVideoPriority` ranking still uses the manifest id.

**Not needed by A2:** the cover stage's own slot-05 film and the hero film are plain `<video>`
elements with `videoManager.reserve('hero-film')` / `reserve('a100-slot5')`, as A1-INTERFACES-READY
says.

Also FYI (no change needed): CoverStage puts `id="a-000"` / `id="a-100"` (+ `data-sheet`) on empty
**track** elements inside the 320vh stage, positioned so `lenisScrollTo('#a-100')` lands at the stage's
end state (P ≈ 0.96), and forwards focus from the track to the A-100 `<h2>` (or the cover `<h1>`).
A third, id-less element registered with `sheetStore.register('A-100', el)` covers the plan-cut and
pull-out range so the SHEET cell ticks to A-100 when the plan appears.
