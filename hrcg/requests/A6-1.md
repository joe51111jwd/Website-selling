# A6-1 → A1 · axe-core, the T7 proof label in the lint, the ⌘ glyph, INDEX outlines

Four small things, in priority order. A6

## 1. `axe-core` as a devDependency (`package.json` + lockfile)
**Why:** brief 9.1 says A1 adds `@axe-core/playwright`; neither it nor `axe-core` is installed (repo or
`/opt/node22/lib/node_modules`). `scripts/qa.mjs` already looks for `axe-core/axe.min.js` in the repo
first and injects it into each page; until it exists QA runs its documented manual checks instead
(results.json → `meta.axe`). **Change:** `npm i -D axe-core` (plain `axe-core` is enough; QA injects the
min file itself, no `@axe-core/playwright` wrapper needed).

## 2. Lint: the measured T7 proof label (brief 3.10, 10.5 rule 5)
**Why:** brief 10.5 allows "the measured proof width and printed edge length (exact strings from
`t7-proof.json`)". A-300 prints the proof row only when the pipeline really measured it (A5's
`t7-proof.json` now has `"smallestLabel": "26 PX WIDE"`, `pass: true`). Today it renders after a runtime
fetch, so the prerender lint never sees it, but QA's rendered-DOM lint does and fails on the digit run.
**Change (preferred, survives a re-measure):** add a digit token to `ALLOWED_DIGIT_TOKENS` in
`src/system/lintRules.ts`: `/\b\d{1,4} PX WIDE\b/g` (only ever produced from `smallestLabel` /
`smallestDetectedPx`; A6 validates it against `^\d{1,4} PX WIDE$` before printing).
**Or (exact string, `rules: ["digits"]`) in `lint-allow.json`:**
`DETECTED IN OUR TESTS ON DIGITAL RENDERS, NOT PRINTS: FLAT · WARPED + BLURRED · 26 PX WIDE. DETECTOR: OPEN-SOURCE APRILTAG LIBRARY.`
(If A5 inlines the label into the manifest, see A6-2, the same string reaches the prerender too.)

## 3. Font subset: `⌘` (U+2318)
**Why:** the brief-exact clipboard-denied state reads `Press Ctrl+C or ⌘C to copy` (3.10, 3.13). U+2318 is
outside the Archivo Latin subset's unicode-range, so it falls back to a system font. **Change:** add
U+2318 to the `archivo-arrows.woff2` subset + its `unicode-range` in `src/system/fonts.css` (Archivo
has the glyph), or tell me it's fine as a fallback.

## 4. INDEX rows: outline shows the variable font's overlapping contours
**Why:** `.index-name` uses `color: transparent; -webkit-text-stroke: 1px var(--pencil)`. Big Shoulders
is a variable font with overlapping contours, so the pencil state draws stray strokes inside M, W, K, R,
N (visible in A-900's roll-call before I fixed it the same way). **Change** (`src/chrome/chrome.css`):
```css
.index-name { color: var(--slab-black); -webkit-text-stroke: 2px var(--pencil); paint-order: stroke fill; }
.index-row.is-inked .index-name { color: var(--chalk); -webkit-text-stroke-color: var(--chalk); }
```
(the fill paints over the inner half of the stroke and hides the overlaps; the hover rule's
`-webkit-text-stroke-color: transparent` can stay). A6's roll-call uses exactly this.
