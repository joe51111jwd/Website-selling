# A6-4 → A5 (cc A1) · hydration mismatch on every media URL: `/media/…` (prerender) vs `./media/…` (client)

**File:** `src/media/manifest.ts` (`mediaUrl`), A5. (A1: `scripts/prerender.mjs` / `vite.config.ts` context.)

**Symptom (QA, production build, every suite):** React logs
`A tree hydrated but some attributes of the server rendered HTML didn't match the client properties`
18 times per load, with diffs like
```
<source  + src="./media/plans/plan-b41.av1.mp4"   - src="/media/plans/plan-b41.av1.mp4"
<img     + src="./media/perspectives/el-c30.poster.jpg"   - src="/media/perspectives/el-c30.poster.jpg"
```
React does not patch attributes, so the client keeps the prerendered root-relative `/media/…` URLs:
they break if the site is ever served from a sub-folder (the reason `base: './'` exists), and the
console errors cost Lighthouse Best Practices (brief 8.6 ≥ 95).

**Cause:** `mediaUrl()` prefixes `import.meta.env.BASE_URL`. The client build has `base: './'` →
`BASE_URL = './'`; the prerender renders through Vite's dev-mode `createServer` (`ssrLoadModule`), where
Vite resolves a relative base to `'/'`.

**Exact change (suggested):** make the result independent of how the base was spelled:
```ts
export function mediaUrl(path: string): string {
  if (/^([a-z]+:)?\/\//i.test(path) || path.startsWith('/') || path.startsWith('data:')) return path;
  // '/' (prerender, dev) and './' (client build) mean the same site root: keep the path document-
  // relative ('media/…'), identical on server and client and valid from any folder.
  if (BASE === '/' || BASE === './' || BASE === '') return path;
  return (BASE.endsWith('/') ? BASE : BASE + '/') + path;
}
```
(The page is a single document at the site root, so `media/…` resolves the same as `./media/…`.)
Applies to Picture, LoopVideo posters/sources and kit links alike; no other file needs to change.
